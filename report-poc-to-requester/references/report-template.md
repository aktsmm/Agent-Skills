# 報告文テンプレート

依頼主へ貼る完成形の骨組み。実際の値は対象検証の結果レポートと記録ファイルから取り、説明用の語句は本文に残さない。

## 構成（この順）

1. **件名**: 「【検証結果のご報告】対象と範囲（項目ID範囲）」。
2. **書き出し**: 実施日（範囲）と、結果を報告する旨を1〜2行。
3. **【先に結論】**: 番号付き3点以内。依頼の核心の問い（成立したか・できなかったか）に、段階・環境・試した範囲を付けて答える。続けて、現状の実測に合う分担案や提案を1行。
4. **【検証の前提】**: 環境（主環境と補助環境の位置づけ）、判定方法、観測回数、環境の注意（反映遅れ、検証用か本番相当か）。
5. **【試したことと結果】**: 項目IDごとに1項目1段落以内。「判定語 + 実測 + 条件」。未実施は未実施と書く。
6. **【呼び方・経路の整理】**: 経路 × 環境の可否を箇条書き。表は貼り先で崩れるため、箇条書きにする。
7. **【残っていること】**: 未確認と、切り分けの次の一手。顧客へ伝えるときの言い方を1行添える。
8. **【後片付けと費用】**: 作ったもの（手動保持・削除はご指示後）、変更していないもの、実環境への影響、費用の概算と未計測。
9. **【記録の所在】**: 検証フォルダー内の相対的な場所と主な成果物名。絶対パスは入れない。画像に業務名が写るときの注意。
10. **結び**: 「よろしくお願いします。」

## 文の作り方

- 判定語は元の記録に合わせる（Verified / Failed / Unverified を日本語にするときは「成立」「不成立」「未確認」など、意味を変えない）。
- 数値は「N件」「N枚」を記録ファイルの `evidence` 件数と一致させる。更新したら件数も更新する。
- 仮説は「仮説:」「未検証」と明示する。
- 「できなかった」の代わりに、「〜の段階まではできた。〜は試した範囲では不成立」と書く。

## チャットでの証跡の示し方

- 文面のコードブロックの後に、「詳細な証跡のフルパス」の節を置く。
- 1行1パス、ドライブ文字から。実在を確認したものだけ。
- 要点の画像は「主張 → ファイル名」の表にし、フォルダーのフルパスを1回だけ書く。
