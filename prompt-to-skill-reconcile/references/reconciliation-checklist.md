# Reconciliation Checklist

Prompt から Skill への移行後に、旧前提を探して分類するための観点。

## 検索パターン

大文字小文字を区別せず、バックスラッシュ区切りも対象にする。

- パス: `.github/prompts`、`*.prompt.md`、旧 Prompt のファイル名（拡張子なし）
- 動詞句: 「prompt を読む」「prompt に従う」「prompt を参照」「対応する prompt」
- 役割の自称: 「task-specific prompt」「この prompt」
- 正本の宣言: 「workflow は prompts を正とする」
- 図・一覧: フロー図のノード名、Dependencies 一覧、README の収録内容・使い方、Skill / agent 一覧

## 検索範囲

- instructions、`AGENTS.md`、`copilot-instructions.md`
- agents（`.agent.md`、templates）、chat modes
- README、docs、Skill の一覧・カタログ
- Skill 本文（`SKILL.md`、references）
- スクリプトの実行処理・生成テンプレート・出力先・その利用側、および docstring・コメント・設定ファイル

履歴記録（議事録、作業ログ、過去回のメモ）は検索結果に出ても、原則として修正対象にしない。

## 分類の目安

| 状況 | 扱い |
| --- | --- |
| 現行の手順で「この Prompt を読む」と案内している | 修正（対応する `SKILL.md` へ） |
| 「正本は prompts」と宣言している | 修正（Skill を正本に） |
| 過去の議事録に旧パスが書かれている | 保持（履歴） |
| LLM に渡す入力文という意味の「プロンプト」 | 保持 |
| Prompt 機能一般の説明（比較表など） | 保持 |
| 移行先 Skill が複数候補、または存在しない | 要判断 |
| 手動呼び出し専用などの挙動設定に関わる | 要判断（変更しない） |

## Skill 側の確認

- `name` がフォルダ名と一致し、移行元の用途が分かる名前になっている
- `description` に「何をするか」と「いつ使うか」がある
- 移行ツールが追加した設定（手動呼び出し専用など）の意味を報告し、変更は承認を取る
- 本文が自身を「prompt」と呼んでいないか
- Skill 一覧に載っている。自動生成ブロックがある場合は、そのブロックの外側に追記する

## 検証の型

1. 旧パス・拡張子の再検索で、修正対象のヒットが 0 件であり、残りが保持分だけであること
2. 修正後に書いた Skill パスが、すべて実在すること
3. 変更ファイルの改行・文字コードが元と一致し、空白エラーがないこと
4. 呼び出し設定と元の担当 agent・tool 権限・承認境界が保たれ、未対応 frontmatter やインライン実行で代替していないこと
5. 実機での呼び出し確認（`/名前` の表示など）は、行っていなければ未確認と報告すること
6. 生成処理がある場合は使い捨ての作業先で実行し、現行ホスト用の入口と参照先が生成され、旧 Prompt 依存が再作成されないこと。モデルへ渡す通常の入力文・互換性説明・負例テストは除外する
