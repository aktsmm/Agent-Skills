# Meeting Prep Rules

Use for a pre-meeting preparation request. Write one prep memo in the next-actions `research/` folder of the coming meeting; keep prep content out of the minutes. Folding prep status into the post-meeting table is handled when the meeting is processed.

## Check First (read-only)

1. Last minutes, the open next-actions board, and open questions.
2. The meeting invite: time, organizer, attendees, and whether the customer sent it.
3. Customer-sent materials since the last meeting. A search that finds nothing means "not found by that search", not "not sent"; report the searched range.
4. Product facts that the last decisions depend on: re-check them against official docs and roadmap, bounded to the period since the last meeting. Label each item by confidence: confirmed in docs / announced only (docs not yet updated) / planned (target date only). Have a second pass verify cited URLs, numbers and states, and state what could not be retrieved.
5. Results already returned from delegated sessions, imported per the material lifecycle.

## Memo Skeleton

- Status: invite, received materials, board state.
- Changes since the last meeting that affect a decision.
- Numbered questions for the customer, each naming its subject.
- Draft agenda as a table with a "decision wanted" column. Mark it unshared until it is sent.
- Unverified items with the condition to re-check.

## Rules

- Event dates and names taken from speech or transcripts are verified against a primary source before they are written down.
- Keep internal drafts, speculation and unshared agendas out of customer-shareable content.
- For findings the user will present, keep source links and separate documented facts from observations in the author's own environment (state the environment and count).
