# Meeting and Goal Inputs

Rules for turning meeting records and a manager's goal/evaluation guidance into workspace records. Use when operating an existing workspace.

## Meeting Records

- Before using a transcript, VTT, or AI meeting note, match its meeting date, duration, and opening speakers to the target meeting. Files for another occurrence of a recurring meeting are easy to receive; move a mismatched file to its own meeting's folder and never merge its content into the target notes.
- Separate items confirmed in the verbatim transcript from items present only in the AI note. Mark AI-note-only items provisional, and verify every number, deadline, and name against the original before recording it as fact.
- If a source file cannot be stored in the workspace (labeled/encrypted Office file, data-loss-prevention block), record only its location and the extracted text needed as evidence; do not claim the file is archived.
- After the meeting, derive follow-up tasks from the notes, then update the task index and every derived view (dashboard, per-customer task file) in the same turn.

## Goal and Evaluation Guidance

- When a manager explains how goals will be judged, record it once as a workspace-level instruction (single source of truth) with source, date, and the speaker's own wording separated from the assistant's interpretation. Other instructions and agents point to it with one line instead of copying it.
- Change those axes only when the user confirms an update, with source and effective date. A new document, a meeting minute, or a meeting having occurred is not itself an update.
- Default classification of an observed activity is "candidate"; promote to "confirmed" only after the axis conditions are checked against primary evidence. Count one achievement once across axes unless the user decides otherwise, and keep "not yet tallied" distinct from zero.
- Use the axes to collect and suggest: daily/weekly/monthly reports, task records, 1-on-1 prep, and career/Connect drafts flag matching activity as candidates and offer low-effort next steps. Executing, sending, or registering anything still needs the user's instruction.
- Store the official role/level definition (the career-level expectations used for promotion and pay) verbatim from its current source, with retrieval date and URL path, as separate reference material. Do not replace it with a summary, do not assume the user's current level, and re-check the current source before an important decision because older copies and pasted summaries can be outdated.
- Compare the manager's axes with the official definition and list expectations the axes do not cover as suggestions; adding them to the axes is the user's decision.
